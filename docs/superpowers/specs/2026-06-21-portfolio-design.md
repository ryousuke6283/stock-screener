# マイポートフォリオ 設計書（MVP）

作成日: 2026-06-21 / 対象リポジトリ: ryousuke6283/stock-screener

## 1. 目的・スコープ

株スクリーナーに「マイポートフォリオ」機能を追加し、現預金と保有株の評価損益を
一元管理できるようにする。スマホ・PCどちらからでも、同じデータを見られる（クラウド同期）。

### MVPに含む
- 現預金（¥）の入力・保存
- 保有株（任意の銘柄）：銘柄・株数・平均取得単価を登録/編集/削除
- 各保有株の現在値・評価額・評価損益（¥ / %）を表示
- 日本株・米国株の混在を ¥ 換算で合算し、総資産・評価損益合計を表示
- 1口座のみ

### MVPに含まない（将来）
- 取引履歴からの自動計算、配当管理、複数口座（NISA/特定）、実現損益
- アラート連携（次フェーズの別機能）

## 2. アーキテクチャ

- アプリを **2ページ構成**にする（`st.navigation`）：
  - 「スクリーナー」… 現状のまま・**公開**
  - 「ポートフォリオ」… 新規・**パスワード保護**
- 肥大化している `app.py` をこの機会に分割（責務を分離）：
  - `lib/data.py` … `load_data` / `usdjpy_rate` / セクター・カタカナ辞書など共有データ
  - `lib/style.py` … `inject_css`（モノトーンデザイン）/ ロゴSVG
  - `lib/format.py` … `fmt` / `compact` / `disp_name`
  - `pages_screener.py` … 現在の画面（移設）
  - `pages_portfolio.py` … 新規
  - `app.py` … エントリ（`st.navigation` でページ束ね）
  - 既存の `test_app.py` は分割に追従して更新

## 3. 認証（パスワード保護）

- ポートフォリオページ**のみ**に簡易パスワードを掛ける（スクリーナーは公開のまま）。
- 合言葉は `st.secrets["PORTFOLIO_PASSWORD"]` に保存。未認証なら `st.text_input(type="password")`
  を表示し、一致したら `st.session_state["pf_auth"]=True` で解除（セッション中有効）。
- セキュリティ水準の明示：これは「合言葉1個」の簡易保護であり、本格的な認証ではない。
  個人利用前提。URLは推測困難だが、合言葉が漏れれば閲覧可能。

## 4. データ構造（Google Sheets）

非公開スプレッドシートに2タブ：

| タブ | 列 | 備考 |
|---|---|---|
| `cash` | `amount_jpy` | 1行のみ。現預金（円） |
| `holdings` | `ticker`, `shares`, `avg_cost` | 1行=1銘柄。`avg_cost`は現地通貨建ての平均取得単価 |

- 銘柄名・通貨・現在値は**保存しない**（毎回 yfinance で取得＝常に最新）。
- 通貨は ticker から判定（`.T` → JPY、それ以外 → USD等）。現在値取得時に通貨も得る。

## 5. 保存先アクセス

- ライブラリ：`gspread` + `google-auth`（サービスアカウント認証）。
- 認証情報は `st.secrets` に格納：
  - `[gcp_service_account]` … サービスアカウントJSONの中身
  - `PORTFOLIO_SHEET_ID` … スプレッドシートID
  - `PORTFOLIO_PASSWORD` … 合言葉
- ローカルは `.streamlit/secrets.toml`（**.gitignore 済み**、絶対コミットしない）。
- 読み書きは薄いラッパ（`lib/store.py`）に隔離：`read_cash()`, `write_cash()`,
  `read_holdings()`, `write_holdings(df)`。テスト時はここをモックする。

## 6. 価格・損益ロジック

- 保有株ごとに現在値・通貨を yfinance で取得（`@st.cache_data` 15分）。少数銘柄なので都度取得で十分。
- 計算（現地通貨）：評価額 = 現在値 × 株数、取得額 = 平均取得単価 × 株数、
  評価損益 = 評価額 − 取得額、損益% = 評価損益 / 取得額。
- ¥換算：USD建ては既存 `usdjpy_rate()` で円換算（為替は別途表示）。
- 合計（¥）：株式評価額合計 + 現預金 = 総資産。評価損益合計(¥)と総取得額比の%。
- 通貨の扱い：MVPは **JPY と USD のみ ¥換算**対応。それ以外の通貨建て銘柄（例: 他国上場）は
  現地通貨で表示し、¥合計には**加えず警告**する（将来、多通貨対応で拡張）。

## 7. UI（ポートフォリオページ）

- デザインは既存の `inject_css` を踏襲：**モノトーン・白/グレー基調**。
  - **ボタンは黒（primary）を使ってよい**（保存などの主要操作）。副次操作は白+細枠。
  - **Material アイコンを出現パターン統一しつつ積極活用**（見出し・メトリクス・ボタンに一貫して付与）。
- 構成：
  1. サマリー（メトリクスグリッド）：総資産(¥)、評価損益(¥ / %)、現預金(¥)、株式評価額(¥)
  2. 現預金：`st.number_input` ＋ 保存ボタン（黒）
  3. 保有株：`st.data_editor`（行の追加/編集/削除）で `ticker, shares, avg_cost` を編集 → 保存ボタンでシート反映
  4. 保有株テーブル（計算結果）：銘柄(カタカナ)・株数・取得単価・現在値・評価額(¥)・損益(¥/%)
  - 損益はモノトーン基調を保ちつつ、**損益だけ機能色**（▲緑 / ▼赤、薄め）でひと目で分かるように。

## 8. エラー処理

- 現在値取得失敗の銘柄：値を「—」表示し、合計からは除外（アプリは落とさない・警告表示）。
- 無効ティッカー：取得結果が空なら警告して保存を促す。
- シート接続失敗：エラー表示＋再試行案内。直近の読み込み結果はキャッシュで一時表示。
- パスワード不一致：エラーメッセージ。

## 9. テスト

- `lib/store.py` をモックし、ネットワーク非依存で損益計算を AppTest 検証：
  - 現地通貨/¥換算の評価額・損益・%、合計、総資産。
  - 取得失敗銘柄の除外、空ポートフォリオ、現預金のみ。
- 既存スクリーナーの AppTest はページ分割に追従して維持。

## 10. 依存追加

`requirements.txt` に `gspread`, `google-auth` を追加。

## 11. ユーザーの手作業（④初期設定・実装の最初に実施）

1. Google スプレッドシートを新規作成（例: `stock-portfolio`）。URL の `/d/<ID>/` の `<ID>` を控える。
2. [Google Cloud Console] で新規プロジェクト作成 → **Google Sheets API** と **Google Drive API** を有効化。
3. サービスアカウントを作成 → キー（**JSON**）を発行・ダウンロード。
4. JSON 内の `client_email`（`...@....iam.gserviceaccount.com`）を、手順1のシートに「共有」→ **編集者**で追加。
5. JSON の中身・シートID・合言葉を `st.secrets`（Streamlit Cloud の Secrets / ローカルは `.streamlit/secrets.toml`）に登録（手順は実装時に伴走）。
